SPAR 2026 · ma-auto-evals · Level 0 + Level 1 auditor on Orbit

An auditor that can steer, rewind and account for a multi-agent run

The auditor can now play an agent (Level 0) or act on the run from outside at the five intervention points in spec §3.2 (Level 1), including rolling back. Every intervention goes through one validated path and is recorded apart from what the agents did on their own. Below are the first live audits on cheap models, then how it is built.

What we found

Two seed scenarios, each run three ways: a baseline with a passive auditor (identical to plain Orbit), a Level 1 audit where an LLM auditor edits one agent's generations and can roll back, and a Level 0 audit where the auditor's model plays that agent. Afterwards every target answers a private belief probe with its own model, and a judge reads that target's own posts. Auditor-written content is never counted as target behaviour.

    Architecture · how it maps to the spec

    Policies never touch Orbit directly. The controller checks each operation (scope, boundary, revision, tool schema), then applies or rejects it and records the outcome with its author: agent:<id> for autonomous output, auditor-as:<id> for content written in an agent's name. Partial edits keep the original. Every seam is off by default, and Orbit's own 6,875 tests pass unchanged.

    Rollback without pretending spec §3.6

    Orbit forbids rolling a run back in place, so a rollback forks instead. The new branch re-runs the real runtime in an isolated store, serving the parent's recorded generations up to the fork point without calling any model. Then it applies the auditor's change and continues live. Every boundary is fingerprinted, so any divergence ends the branch as replay_desync. Only tools declared pure are re-run, so effects can't leak between branches. The budget counts every branch and is never refunded.

    For discussion

    Next decisions and known limits

    For Will and Tom

    Rollback design: fork and replay is built and tested as agreed. Is it the design we want upstream? Upstreaming: the seven seams are small, default-off commits, ready to split into Orbit PRs. Seeds: keep these two, or start from Tili's scenarios for §7.1? Scale: three runs per cell show the tool works; claims will need bigger runs.

    Known limits

    Rollback is refused when defenses or model filters are in the loop, and for tools not declared pure; both fail closed. Auditor-written outputs skip output defenses, though they are attributed. The judge is provisional. Real models broke five assumptions the mocks couldn't, all now fixed: Llama writes tool calls as text, Gemini Flash-Lite runs away, agents waste turns on reads, OpenRouter enforces strict schemas, and model clients outlive their event loop.
